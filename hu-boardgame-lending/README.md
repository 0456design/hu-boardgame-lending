# ระบบยืม-คืนบอร์ดเกมและอุปกรณ์

เว็บแอประบบยืม-คืนบอร์ดเกม — ไม่ต้องติดตั้ง dependency ใดๆ เลย
(ใช้ `node:sqlite` และ `http` ซึ่งเป็นโมดูลในตัวของ Node.js)

## แนวคิดหลัก: ผู้ใช้ "ขอยืม" — เจ้าหน้าที่ "ยืนยันการยืมจริง"

ผู้ใช้ทั่วไปกดยืมแล้วถือว่ายืมสำเร็จทันทีไม่ได้ ฝั่งผู้ใช้เป็นระบบ **ดูเกม → ตรวจว่าว่างหรือไม่ → ส่งคำขอยืม → รอเจ้าหน้าที่ดำเนินการ**

```
หน้าแรก → ค้นหาเกม → ดูรายละเอียด → ขอยืมเกม → กรอกข้อมูล → ตรวจสอบคำขอ → ส่งคำขอยืม
   → [รอเจ้าหน้าที่ดำเนินการ]  (ชุดเกมยังเป็น "พร้อมให้ขอยืม" ไม่เปลี่ยน)
   → เจ้าหน้าที่ตรวจสอบที่หน้า "คำขอยืม"
        ├─ อนุมัติ / ดำเนินการยืม → สร้างรายการยืมจริง ชุดเป็น "กำลังถูกยืม" → ผู้ใช้เห็นที่ "การยืมของฉัน"
        ├─ ปฏิเสธ (ใส่หมายเหตุได้)
        └─ ยกเลิก
   → ผู้ใช้นำเกมมาคืนกับเจ้าหน้าที่ → เจ้าหน้าที่กด "รับคืน" → [คืนแล้ว]
```

- **คำขอ (`loan_requests`) แยกจากรายการยืม (`loans`)** — ส่งคำขอไม่เปลี่ยนสถานะชุดเกม การยืมจริงเกิดตอนเจ้าหน้าที่อนุมัติเท่านั้น
- ผู้ใช้ **ไม่มี** ปุ่มยืนยันการยืม / เปลี่ยนสถานะชุด / เปลี่ยนสถานะเป็นยืมหรือคืนแล้ว — และเซิร์ฟเวอร์บังคับด้วย: `POST /api/loans` และ `POST /api/loans/:id/return` ต้อง Login เจ้าหน้าที่ (ผู้ใช้เรียกตรงไม่ได้)
- ปุ่ม "แจ้งคืนเกม" ของผู้ใช้เป็นแค่ข้อความให้นำเกมมาคืนกับเจ้าหน้าที่ ไม่เปลี่ยนสถานะใดๆ
- ผู้ใช้ยกเลิกคำขอเองได้ **เฉพาะสถานะ "รอเจ้าหน้าที่ดำเนินการ"** (เซิร์ฟเวอร์ตรวจซ้ำ และตรวจว่ารหัสนักศึกษาตรงกับเจ้าของคำขอ)
- ถ้าชุดที่ผู้ใช้ขอไม่ว่างแล้วตอนอนุมัติ (เช่น ส่งซ่อม) เจ้าหน้าที่เลือกชุดอื่นของเกมเดียวกันที่ว่างให้แทนได้ในหน้าต่างอนุมัติ
- คำขอที่ถูกปฏิเสธ/ยกเลิก เจ้าหน้าที่กด "เปิดเป็นรอดำเนินการ" เพื่อตรวจสอบใหม่ได้ · คำขอที่อนุมัติแล้วย้อนไม่ได้ (ถ้ายืมผิดให้ "รับคืน")

## ระบบยืมอุปกรณ์ (โน๊ตบุ๊ค / กล้อง VR / ปลั๊กไฟ)

หน้า `/equipment.html` ใช้ดีไซน์และกติกาเดียวกับหน้าบอร์ดเกม — ผู้ใช้ **ขอยืม** แล้วเจ้าหน้าที่ **อนุมัติ/ดำเนินการยืมจริง** แล้ว **รับคืน**

```
เลือกอุปกรณ์ → ข้อมูลผู้ยืม (รหัสนักศึกษา/ชั้นปี/คณะ/สาขา) → ตรวจสอบ → เสร็จสิ้น (ส่งคำขอแล้ว รอเจ้าหน้าที่)
   → เจ้าหน้าที่อนุมัติที่หน้า "คำขอยืม" → รายการเป็น "กำลังถูกยืม" และแสดงที่ "การยืมของฉัน" → เจ้าหน้าที่ "รับคืน"
```

- การ์ดอุปกรณ์แสดงชื่อ ไอคอน จำนวนที่ว่าง (เช่น ว่าง 3/4 รายการ) และสถานะ · เลือกรายการย่อย (เช่น โน๊ตบุ๊ค 1–4) ได้ในขั้นที่ 1
- กติกา: 1 รหัสนักศึกษามีคำขออุปกรณ์ที่รอดำเนินการได้ 1 คำขอ และยืมอุปกรณ์ค้างได้ครั้งละ 1 รายการ (**นับแยกจากสิทธิ์ยืมบอร์ดเกม**) · ระยะเวลายืม 2 ชั่วโมง (ค่า `LOAN_MINUTES` เดียวกับบอร์ดเกม)
- **การยืมของฉัน / คำขอของฉัน** แสดงทั้งบอร์ดเกมและอุปกรณ์ในกรอบเดียวกัน มีป้ายประเภทและตัวกรอง ทั้งหมด/บอร์ดเกม/อุปกรณ์ · รหัสอุปกรณ์ขึ้นต้น `EQR-` (คำขอ) และ `EQ-` (รายการยืม) ค้นด้วย `EQ-12` ได้
- **หน้าเจ้าหน้าที่**: เมนู "คำขอยืม" และ "การยืม–คืน" รวมทั้งสองประเภท (แยกด้วยป้าย) · เมนู "อุปกรณ์" ยังจัดการเพิ่ม/แก้ไข/ลบ/เปลี่ยนสถานะได้เหมือนเดิม · สถิติและรายชื่อผู้ยืมนับรวมการยืมอุปกรณ์ด้วย
- ตารางใหม่ `equipment_requests` และ `equipment_loans` ถูกสร้างอัตโนมัติ — **ข้อมูลเดิมใน `data.db` ไม่ถูกแก้ไข/ลบ**

### ออกจากระบบ (เจ้าหน้าที่)
กด "ออกจากระบบ" จะขึ้นกล่องยืนยัน "ต้องการออกจากระบบหรือไม่?" (ดีไซน์เดียวกับกล่องยืนยันอื่นของระบบ) — **ยกเลิก** = ปิดกล่องและอยู่หน้าเดิม · **ออกจากระบบ** = Logout และกลับหน้า Login

### API อุปกรณ์เพิ่มเติม
| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/equipment` | รายการอุปกรณ์พร้อมรายการย่อยและสถานะ (เปิดให้ผู้ใช้ทั่วไปดูได้) |
| POST | `/api/equipment-requests` | **ผู้ใช้** ส่งคำขอยืมอุปกรณ์ `{copy_id, student_id, year_level, faculty, major}` |
| GET | `/api/equipment-requests?student=รหัส` | **ผู้ใช้** ดูคำขอของรหัสนั้น (ไม่ส่ง `student` = ทั้งหมด → เจ้าหน้าที่เท่านั้น) |
| POST | `/api/equipment-requests/:id/cancel` | **ผู้ใช้** ยกเลิกคำขอของตัวเอง (เฉพาะ `pending`) |
| PATCH | `/api/equipment-requests/:id` | **เจ้าหน้าที่** อนุมัติ/ปฏิเสธ/ยกเลิก/เปิดใหม่ `{status, note?, copy_id?}` |
| GET | `/api/equipment-loans?borrower=รหัส` หรือ `?code=เลข` | รายการยืมอุปกรณ์ของผู้ยืม (ไม่ระบุ = ทั้งหมด → เจ้าหน้าที่เท่านั้น) |
| POST | `/api/equipment-loans/:id/return` | **เจ้าหน้าที่เท่านั้น** บันทึกการคืน |

## กติกาที่ตั้งไว้
- ส่งคำขอได้ครั้งละ **1 คำขอที่รอดำเนินการ ต่อ 1 รหัสนักศึกษา** และส่งไม่ได้ถ้ามีเกมที่ยังไม่คืนอยู่
- ยืมได้ **1 รายการ ต่อ 1 สิทธิ์** (ยืมค้างอยู่ 1 เกม จะยืมเพิ่มไม่ได้จนกว่าจะคืน)
- ระยะเวลายืม **2 ชั่วโมง** ต่อครั้ง (ระบบคำนวณเวลาครบกำหนดให้อัตโนมัติ)
- ไม่มีระบบจองล่วงหน้า — ยืมได้เฉพาะชุดที่ว่างตอนนั้น
- เกม 1 ชื่อ มีได้หลายชุด/สำเนา (แยกติดตามสถานะแต่ละชุดอิสระกัน)

## วิธีรัน

ต้องมี **Node.js เวอร์ชัน 22 ขึ้นไป** (เพราะใช้ `node:sqlite` ซึ่งยังเป็นฟีเจอร์ experimental)

```bash
node server.js
```

แล้วเปิดเบราว์เซอร์ไปที่:
- หน้าหลัก (ดูเกม/ขอยืม): http://localhost:3000
- คำขอของฉัน (ติดตามสถานะ/ยกเลิกคำขอ): http://localhost:3000/myrequests.html
- การยืมของฉัน (รายการที่เจ้าหน้าที่ดำเนินการยืมให้แล้ว/กำหนดคืน): http://localhost:3000/myloans.html
- หน้าเจ้าหน้าที่ (จัดการเกม/ดูรายการยืม/ผู้ยืม): http://localhost:3000/admin.html — **ต้อง Login ก่อน** (ถ้ายังไม่ Login จะถูกพาไปหน้า `/login.html`)

ข้อมูลจะถูกเก็บในไฟล์ `data.db` (SQLite) ที่จะถูกสร้างอัตโนมัติตอนรันครั้งแรก พร้อมเกมตัวอย่าง 4 เกมให้ทดลองใช้

## โครงสร้างไฟล์

```
server.js              → HTTP server + REST API (ไม่ใช้ framework)
auth.js                → TEST LOGIN เจ้าหน้าที่ (session คุกกี้) + ตัวระบุผู้โหวต
db.js                  → เชื่อมต่อฐานข้อมูล SQLite, schema, query ทั้งหมด
public/
  equipment.html/.js      → หน้ายืมอุปกรณ์: เลือกอุปกรณ์ → ข้อมูลผู้ยืม → ตรวจสอบ → เสร็จสิ้น
  index.html/app.js       → หน้าแรก: ค้นหา/ดูรายละเอียด/ส่งคำขอยืม (สำหรับผู้ใช้ทั่วไป)
  myrequests.html/.js     → คำขอของฉัน: ค้นด้วยรหัสนักศึกษา ดูสถานะ/รายละเอียด/ยกเลิกคำขอ
  myloans.html/myloans.js → การยืมของฉัน: แสดงเฉพาะรายการที่เจ้าหน้าที่ยืมให้แล้ว + "แจ้งคืนเกม"
  admin.html/admin.js     → หน้าเจ้าหน้าที่: ภาพรวม/คำขอยืม/จัดการเกม/การยืม-คืน/ผู้ยืม (ต้อง Login)
  login.html/login.js     → หน้า Login เจ้าหน้าที่
  style.css               → ธีมหน้าตา (โทนน้ำเงิน–ขาวของมหาวิทยาลัยหาดใหญ่)
data.db                → ฐานข้อมูล (สร้างอัตโนมัติ)
```

## ฟีเจอร์ที่เพิ่มล่าสุด

- **สถิติแยกคณะ/สาขา + เก็บข้อมูลถาวร** — หน้า "สถิติ" มี 3 มุมมอง: รายวัน (กดแต่ละวันดูแยกคณะ→สาขา), สรุปรายเดือน และรายปี (นับตามเวลาไทย UTC+7)
  - ประวัติการยืม (`loans`) และคะแนนโหวต (`game_ratings`) เก็บชื่อเกม/ชุดไว้ในแถวเอง และไม่ถูกลบตามเมื่อลบเกม/ชุด — สถิติและโหวตจึงอยู่ถาวร (ระบบย้ายตารางเดิมให้อัตโนมัติตอนรันครั้งแรก ข้อมูลเดิมไม่หาย)

- **ระบบ "ขอยืม" (ฝั่งผู้ใช้) + หน้า "คำขอยืม" (ฝั่งเจ้าหน้าที่)** — ดูหัวข้อ "แนวคิดหลัก" ด้านบน
  - สถานะบนการ์ดเกม: พร้อมให้ขอยืม · 🟡 มีบางชุดถูกยืม · ไม่มีชุดว่าง · ⚙️ ซ่อมบำรุง (กรองตามสถานะเหล่านี้ได้)
  - ปุ่มบนการ์ด/หน้ารายละเอียดเป็น "ขอยืมเกม" / "ไม่มีชุดว่าง" (กดไม่ได้)
  - ฟอร์มส่งคำขอ: รหัสนักศึกษา (ตัวเลขเท่านั้น) · ชั้นปี · คณะ · สาขา (เปลี่ยนตามคณะ) → หน้า "ตรวจสอบคำขอยืม" → ส่งคำขอ
  - สถานะคำขอ: 🟡 รอเจ้าหน้าที่ดำเนินการ · เจ้าหน้าที่ดำเนินการยืมให้แล้ว · คำขอถูกปฏิเสธ · ⚪ คำขอถูกยกเลิก
  - ฝั่งเจ้าหน้าที่: เมนู "คำขอยืม" (มีตัวเลขจำนวนที่รอดำเนินการ) และรายการ "ที่ต้องดำเนินการ" ในหน้าภาพรวม
  - ตาราง `loan_requests` ถูกสร้างอัตโนมัติเมื่อรันครั้งแรก — **ข้อมูลเดิมใน `data.db` ไม่ถูกแก้ไข/ลบ**
  - ซ่อมปุ่ม "ล้างตัวกรอง" ที่เดิมกดแล้วไม่ล้างค่า (ปุ่ม `id="reset"` ไปบังเมธอด `form.reset()`)

- **TEST LOGIN เจ้าหน้าที่** — หน้า `/login.html`, ปุ่ม "ออกจากระบบ" ที่แถบเมนูซ้ายของหน้าเจ้าหน้าที่
  - ยังไม่ Login เปิด `/admin.html` ไม่ได้ (redirect ไปหน้า Login) และ API ฝั่งเจ้าหน้าที่ (จัดการเกม/อุปกรณ์/สถิติ/ผู้ยืม/รายการยืมทั้งหมด) จะตอบ 401
  - มีบัญชีเจ้าหน้าที่ 2 บัญชี (`hucom1`, `hucom2`) กำหนดไว้ใน `auth.js` เปลี่ยนได้โดยไม่ต้องแก้โค้ดด้วย env เช่น `STAFF_ACCOUNTS="user1:รหัส1,user2:รหัส2" node server.js` ไม่ถูกแสดงในหน้าเว็บ — เป็นระบบทดสอบ ยังไม่ใช่ระบบสมาชิกจริง
- **อัปเดตหน้าอัตโนมัติ (เรียลไทม์):** หน้าผู้ใช้ หน้า "การยืมของฉัน" และหน้าเจ้าหน้าที่ของทุกคนอัปเดตเองทันทีเมื่อมีการยืม/คืน/ให้คะแนน/แก้ไขข้อมูล (ใช้ Server-Sent Events ที่ `/api/events` ไม่ต้องติดตั้งอะไรเพิ่ม) ใช้ได้เมื่อทุกคนเข้าผ่านเซิร์ฟเวอร์ตัวเดียวกัน
- หน้ายืมเกม: เลือก **คณะ** แล้วจึงเลือก **สาขา** (แสดงเฉพาะสาขาของคณะนั้น) รายชื่ออยู่ที่ `public/faculties.js` ไฟล์เดียว และเซิร์ฟเวอร์ตรวจซ้ำว่าสาขาอยู่ในคณะที่เลือก
  - ผิดรหัส 5 ครั้งติดกัน ถูกล็อก 60 วินาที · session อยู่ได้ 8 ชั่วโมง (เก็บในหน่วยความจำ รีสตาร์ทเซิร์ฟเวอร์แล้วต้อง Login ใหม่)
- **การยืมของฉัน** — รายการยืมทั้งหมดอยู่ใน Container (กรอบ) เดียวขนาดเท่ากรอบเดิม เรียงต่อกันภายใน และเลื่อน (scroll) ภายในกรอบเมื่อมีจำนวนมาก
- **Rating บอร์ดเกม 1–5 ดาว** — แสดงค่าเฉลี่ย + จำนวนโหวตบนการ์ดเกม กดดาวเพื่อให้คะแนน อัปเดตทันทีโดยไม่ต้อง refresh
  - เก็บในตาราง `game_ratings` (SQLite) 1 ผู้โหวตต่อ 1 เกม: โหวตซ้ำ = แก้คะแนนเดิม ไม่เพิ่มจำนวนโหวต
  - ผู้โหวตระบุด้วยคุกกี้นิรนามต่อเบราว์เซอร์ (`hu_voter`) เพราะยังไม่มีระบบสมาชิก → ล้างคุกกี้/ใช้เบราว์เซอร์อื่นจะโหวตซ้ำได้ ถ้าต้องการเข้มงวดกว่านี้ให้ผูกกับบัญชีผู้ใช้จริงโดยแก้ `getVoterId()` ใน `auth.js` เพียงที่เดียว
- **เวลาเล่น** ของ Blocks 54 pcs / Ice Break / Midnight (ค่าประมาณ แก้ได้ที่หน้าเจ้าหน้าที่ → บอร์ดเกม → แก้ไข) — เติมให้อัตโนมัติครั้งเดียวตอนเริ่มระบบ (ไม่เขียนทับถ้าเจ้าหน้าที่แก้ภายหลัง)

- **ขั้นตอนการยืม** แสดงตัวบอกขั้น 1 เลือกชุด → 2 ข้อมูลผู้ยืม → 3 ตรวจสอบ → 4 เสร็จสิ้น (ขั้นปัจจุบันเน้นสี, ขั้นที่ผ่านแล้วขึ้นเครื่องหมายถูก)
- **หน้าเลือกชุด** มีช่องกรอก ชั้นปี / สาขา / คณะ (บังคับกรอก และบันทึกไว้กับรายการยืม)
- **รหัสนักศึกษา** กรอกได้เฉพาะตัวเลข (ตรวจทั้งหน้าเว็บและฝั่งเซิร์ฟเวอร์)
- **หน้าเจ้าหน้าที่ → อุปกรณ์** (อยู่ใต้ "บอร์ดเกม") หน้าตา/การใช้งานเหมือนบอร์ดเกม: โน๊ตบุ๊ค 4, กล้อง VR 2, ปลั๊กไฟ 5 (เพิ่ม/แก้ไข/ลบ และเปลี่ยนสถานะพร้อมให้ยืม/กำลังถูกยืม/ซ่อมบำรุงได้)
- **เปลี่ยนรูปบอร์ดเกม** ที่หน้าเจ้าหน้าที่ → บอร์ดเกม → ปุ่ม "รูปภาพ": ลบรูปเดิม → เลือกไฟล์ใหม่ → บันทึก
  รูปจะถูกเก็บในโฟลเดอร์ `uploads/games/` (ไฟล์เก่าถูกลบจริง) และหน้าผู้ใช้แสดงรูปใหม่ทันที
  รองรับ JPG / PNG / WEBP / GIF ขนาดไม่เกิน 5 MB — **ต้องสำรองโฟลเดอร์ `uploads/` ไว้คู่กับ `data.db`**

## API หลักๆ

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/games` | รายชื่อเกมทั้งหมดพร้อมชุดและสถานะ + `rating_avg` / `rating_count` / `my_rating` |
| POST | `/api/games/:id/rating` | ให้คะแนนเกม `{rating: 1-5}` (คนเดิมโหวตซ้ำ = แก้คะแนน) |
| POST | `/api/login` · `/api/logout` · GET `/api/session` | TEST LOGIN เจ้าหน้าที่ |
| POST | `/api/games` | เพิ่มเกมใหม่ |
| PUT | `/api/games/:id` | แก้ไขข้อมูลเกม (ชื่อ/จำนวนผู้เล่น/เวลา/คำอธิบาย) |
| DELETE | `/api/games/:id` | ลบเกม (และทุกชุดของเกมนั้น) — ลบไม่ได้ถ้ามีชุดถูกยืมอยู่ |
| POST | `/api/games/:id/image` | อัปโหลดรูปเกม (ส่งไฟล์รูปเป็น body ตรงๆ) แทนรูปเดิม และลบไฟล์เก่า |
| DELETE | `/api/games/:id/image` | ลบรูปของเกม (ลบไฟล์จริง) |
| GET/POST | `/api/equipment` | รายการ / เพิ่มอุปกรณ์ |
| PUT/DELETE | `/api/equipment/:id` | แก้ไข / ลบอุปกรณ์ |
| POST | `/api/equipment/:id/copies` | เพิ่มรายการย่อย (เช่น โน๊ตบุ๊ค 5) |
| PATCH/DELETE | `/api/equipment-copies/:id` | เปลี่ยนสถานะ / ลบรายการย่อย |
| POST | `/api/games/:id/copies` | เพิ่มชุด/สำเนาให้เกม (ตั้งชื่อ "ชุดที่ N" อัตโนมัติ) |
| DELETE | `/api/copies/:id` | ลบชุดเกม — ลบไม่ได้ถ้าชุดนั้นถูกยืมอยู่ |
| PATCH | `/api/copies/:id` | เปลี่ยนสถานะชุด (ว่าง/ซ่อมบำรุง) |
| POST | `/api/requests` | **ผู้ใช้** ส่งคำขอยืม `{copy_id, student_id (ตัวเลขเท่านั้น), year_level, faculty, major}` → สถานะ `pending` (ไม่เปลี่ยนสถานะชุดเกม) |
| GET | `/api/requests?student=รหัส` | **ผู้ใช้** ดูคำขอของรหัสนั้น (ไม่ส่ง `student` = ดูทั้งหมด → เจ้าหน้าที่เท่านั้น) |
| POST | `/api/requests/:id/cancel` | **ผู้ใช้** ยกเลิกคำขอของตัวเอง `{student_id}` — ได้เฉพาะสถานะ `pending` |
| PATCH | `/api/requests/:id` | **เจ้าหน้าที่** เปลี่ยนสถานะคำขอ `{status: approved/rejected/cancelled/pending, note?, copy_id?}` — `approved` = สร้างรายการยืมจริง |
| POST | `/api/loans` | **เจ้าหน้าที่เท่านั้น** สร้างรายการยืมโดยตรง `{copy_id, borrower_name (ตัวเลขเท่านั้น), year_level, major, faculty}` |
| POST | `/api/loans/:id/return` | **เจ้าหน้าที่เท่านั้น** บันทึกการคืน |
| GET | `/api/loans?active=true` | รายการที่ยังไม่คืน |
| GET | `/api/loans?borrower=รหัสนักศึกษา` | รายการยืม (ทั้งหมด/ค้าง) ของผู้ยืมคนหนึ่ง — ใช้โดยหน้า "การยืมของฉัน" |
| GET | `/api/loans?code=รหัส` | ค้นหารายการยืมด้วยรหัสการยืม (คือ id ของ loan) — อีกทางเลือกในหน้า "การยืมของฉัน" นอกจากค้นด้วยชื่อ |
| GET | `/api/stats` | สรุปตัวเลขสำหรับ Dashboard แอดมิน (จำนวนเกม/ชุดว่าง/ถูกยืม/เกินกำหนด/ผู้ยืม) |
| GET | `/api/borrowers` | สรุปรายชื่อผู้ยืม พร้อมจำนวนครั้งที่ยืม — ใช้แทนระบบบัญชีผู้ใช้ (ดูหมายเหตุด้านล่าง) |

## สิ่งที่ยังไม่ทำ (จุดต่อยอดในอนาคต)

- **ยังไม่มีระบบสมัคร/ล็อกอินสมาชิกจริง** — ตอนนี้ระบุตัวตนผู้ยืมด้วย "ชื่อ" ที่พิมพ์เข้าไปตรงๆ (ใช้ตรวจกฎ 1 สิทธิ์/คน, หน้า "การยืมของฉัน" ก็ค้นด้วยชื่อนี้เช่นกัน) หน้าแอดมิน → แท็บ "ผู้ยืม" จึงเป็นแค่สรุปจากชื่อในประวัติการยืม ไม่ใช่บัญชีผู้ใช้จริง เหมาะกับการใช้งานในวงเล็ก/ที่ไว้ใจกันได้ แต่ถ้าจะใช้งานจริงจัง (เช่น ผูกกับรหัสนักศึกษา) ควรเพิ่มระบบสมาชิก/ล็อกอิน
- ยังไม่มีระบบแจ้งเตือนอัตโนมัติ (อีเมล/LINE) เมื่อใกล้ครบกำหนดหรือเกินเวลา — ตอนนี้เห็นสถานะ "ใกล้ครบกำหนด/เกินเวลา" ได้จากหน้า "การยืมของฉัน" และหน้าแอดมิน (แท็บภาพรวม → รายการที่ต้องติดตาม) เท่านั้น
- ยังไม่มีหมวดหมู่เกม (category) แยกต่างหาก — ตอนนี้ค้นหาได้จากชื่อเกมเท่านั้น
- "ดูรายละเอียดเกม" ใช้หน้าต่าง (modal) แทนการมี URL หน้าแยกต่างหาก เพื่อความเรียบง่ายของโค้ด (ไม่มี framework/router)
